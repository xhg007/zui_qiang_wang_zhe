# AI 智怼助手

> 一款**辩论辅助**浏览器扩展，而不是网络暴力加速器。

在 X / 微博上，每条评论的操作栏里会多出一个「AI 回复」按钮。点它 → 自动读这条评论（详情页就连同上面几轮讨论一起读）→ 流式生成一段有理有据的草稿 → 你改完、一键填进回复框，**最后仍由你亲手点发送**。

技术栈：**WXT + Vue 3 + TypeScript**；AI 接入走 OpenAI 兼容协议（官方 `openai` SDK，含流式），内置 5 家国内供应商预设 + 自定义供应商。

## 它是什么 / 不是什么

**是什么**

面对一条史实错误、逻辑漏洞或人身攻击的评论，帮你快速写出一段站得住脚的回复。三种触发方式：

1. **评论内按钮**：每条评论的操作栏里自动出现「AI 回复」，不用先选中文字。
2. **选中浮按钮**：在评论里选中任意文字，浮出「AI 回复」。
3. **popup 粘贴**：点扩展图标，把文字粘进去生成。

**不是什么**

- 不是群发工具：没有批量回复，没有定时发送。
- 不会自动发送：不调用平台发布接口，不模拟点击「发送」。
- 不替你决定内容：草稿永远可编辑，事实需要你自己核对。

## 功能

| 编号 | 功能 | 状态 | 说明 |
| :--- | :--- | :--- | :--- |
| F1 | 页面文本捕获 | ✅ | 评论内按钮 / 选中浮按钮 / popup 粘贴，三条路径都带昵称与正文 |
| F2 | AI 回复生成 | ✅ | background 单一网络出口；30 秒请求超时；流式输出；错误码翻译成中文 + 重试 |
| F3 | 回复风格 | ✅ | 🧊 理性反驳 / 🎭 幽默反讽 / 🔥 灵魂拷问，各自独立 Prompt 片段 |
| F4 | 审核发送 | ✅ | 可编辑草稿气泡：重新生成、换风格重生成、恢复上一版、复制、一键填入平台回复框 |
| F5 | 供应商管理 | ✅ | 5 家预设 + 自定义（OpenAI 兼容）；切换时模型 / Key / hint 三联动；Key 独立存本机；测试连接；Key 申请直达链接 |
| F6 | 上下文多轮 | ✅ | 详情页自动带同一讨论串前 4 轮，Prompt 中按时间正序呈现 |
| F7 | 自定义 Prompt | ✅ | 设置页可查看 / 编辑 / 恢复默认三风格的系统提示与风格指令，支持变量 |
| F8 | 自定义供应商 | ✅ | 已并入 F5 的「自定义（OpenAI 兼容）」一项，保存时按需申请域名权限 |
| F9 | 情绪预分析 | ✅ | 生成前判断对方语气（愤怒 / 讽刺 / 挑衅 …），面板显示并据此调整策略，可关闭 |

生成结果开头固定带 `🤖` 标识（默认开启、不可关闭）；Prompt 内置禁止脏话 / 歧视 / 人身攻击的硬约束，并要求 100-200 字——**这些硬约束由程序追加，即使用户自定义了 Prompt 也删不掉**。

## 合规边界（重要）

- **没有任何自动发送能力**：不调用平台发布接口，不模拟点击「发送」按钮，不做批量回复。
- **「填入回复框」只做写入**：把文本写进平台的回复编辑器（编辑器没打开时，会替你点一下「回复」把它打开），然后提示你检查、自己点发送。写入失败会自动回退为复制到剪贴板。
- **首次生成前明确告知**：评论文本会发送到你选择的 AI 供应商；插件不设中转服务器、不采集浏览记录。
- **不做中间层**：请求从浏览器直连供应商，产品方不代理、不落库。

## 快速开始

```bash
pnpm install
pnpm dev        # 开发模式：启动带扩展的浏览器，改代码自动重载
pnpm build      # 生产构建到 .output/chrome-mv3
pnpm typecheck  # vue-tsc 类型检查
pnpm test       # vitest 单测（29 个用例）
pnpm zip        # 打包上架用的 zip
```

手动加载：Chrome / Edge → `chrome://extensions` → 打开「开发者模式」→「加载已解压的扩展程序」→ 选 `.output/chrome-mv3`。

## 使用

生成后面板会停在页面右下角（不遮挡你正在看的评论），里面是对话式的三段内容：对方评论 → 系统提示（识别到的语气 / 带上了几轮上文）→ AI 回复气泡。

| 操作 | 位置 | 说明 |
| :--- | :--- | :--- |
| 换风格 | 底部 chip | 换风格会**自动重生成**（已有草稿或报错时） |
| 重新生成 | `↻` | 会把当前稿存为「上一版」，并提示模型换个角度 |
| 恢复上一版 | `↩` | 与当前稿来回切换，防止手改的内容被覆盖丢失 |
| 复制 | `⧉` | 只复制，不发任何东西 |
| 填入回复框 | 渐变胶囊 | 写入平台编辑器并滚到视野中央；失败回退复制 |
| 关闭 | 右上角 `✕` 或 `Esc` | 焦点在输入框里时 Esc 不关闭，避免打字误关 |

## 配置供应商（三步）

设置页里：

1. **选供应商** —— DeepSeek / 通义千问 / Kimi / 智谱 GLM / 硅基流动 / 自定义。首次安装不预选。
2. **粘贴 API Key** —— 每家都有「去申请」直达链接。
3. **测试连接** —— 用当前配置发一次最小请求。

切换供应商时，模型自动回到该家默认值、Key 输入框自动加载该家已存的 Key、提示文案同步更新；各家 Key 互相独立，来回切换不会丢。

自定义供应商填任意 OpenAI 兼容地址（如 `https://your-host/v1`）与模型名；保存或测试时按需申请该域名权限，不预先占用宽泛权限。

**错误码对照**

| 提示 | 含义 | 怎么办 |
| :--- | :--- | :--- |
| 401 | Key 无效 / 过期；通义千问的 Key 与地域不匹配 | 重新复制 Key（别带空格引号）；确认开通地域 |
| 403 | Key 无权访问该模型 | 到控制台开通该模型 |
| 404 | base URL 少了 `/v1` 或填错 | 预设供应商不要手改地址；自定义补齐 `/v1` |
| 400 | 模型名不被支持 | 换一个预置模型 |
| 429 | 限流或余额不足 | 稍后重试 / 充值 |
| 超时 | 请求 30 秒未返回，或流式 45 秒无新内容 | 重试或换一家更快的供应商 |
| 网络 | 连不上 / 代理 / 域名权限未授予 | 检查网络代理；自定义供应商重新保存以授权 |

## 架构

```
entrypoints/
├── background.ts        # 唯一网络出口：消息路由 + 流式 port（生成 / 测试连接 / 状态）
├── content.ts           # 评论按钮注入 + 选区捕获 + Shadow DOM 草稿面板
├── popup/               # 粘贴文本快速生成
└── options/             # 设置：供应商 / Key / 测试连接 / 生成选项 / 统计 / Prompt 模板
lib/
├── providers.ts         # 预设供应商数据表（纯数据）
├── storage.ts           # 存储封装 + resolveActiveProvider()
├── prompts/             # 三风格模板、变量替换、硬约束、🤖 标识
│   ├── index.ts         #   buildMessages / applyPromptVars / finalizeDraft
│   └── styles.ts        #   风格元数据与默认策略
├── adapters/            # 站点适配
│   ├── sites.ts         #   选择器数据表（评论 / 操作栏 / 回复框 / 讨论串）
│   └── index.ts         #   通用解析：取评论、收上下文、填入编辑器
├── injector.ts          # 评论内「AI 回复」按钮注入（增量扫描 + 去重 + 可清理）
├── ai.ts                # openai SDK 封装（普通 + 流式）
├── stream.ts            # 流式 port 客户端（含 45 秒空闲看门狗）
├── emotion.ts           # 语气分类与应对策略（F9）
├── errors.ts            # HTTP / 网络错误 → 中文文案
├── client.ts            # UI → background 消息、域名权限申请
├── metrics.ts           # 本机使用统计（生成 / 复制 / 填入 / 耗时）
└── messaging.ts         # 消息、流式协议与结果类型
components/
├── ContentOverlay.vue   # 页面内交互层：选区浮按钮、面板开合、Esc、填入与 toast
├── DraftPanel.vue       # 草稿面板：对话区、生成状态、错误恢复
├── DraftComposer.vue    # 底部动作条：风格 chip + 重新生成 / 复制 / 撤销 / 填入
├── ConsentBubble.vue    # 首次隐私告知气泡
└── StylePicker.vue      # 风格选择
assets/theme.css         # 社交 App 卡片风设计令牌（三处 UI 共用，含明暗两套）
public/icon/             # 扩展图标（16/32/48/96/128，WXT 自动写进 manifest.icons）
vitest.config.ts         # 单测配置（happy-dom）
prd.md                   # 需求文档（验收口径以它为准）
```

**数据流**

```
content script / popup
        │  browser.runtime.connect('ai-stream')
        ▼
background（唯一网络出口，读配置 → 组装 Prompt）
        │  openai SDK（stream: true）
        ▼
供应商 API（DeepSeek / 通义 / Kimi / 智谱 / 硅基流动 / 自定义）
        │  chunk · chunk · …
        ▼
草稿面板逐字渲染 ──onDone──▶ 用带 🤖 的终稿覆盖
```

**关键约束**

- **供应商差异只在 `lib/providers.ts`**：新增供应商 = 加一条数据；`wxt.config.ts` 的 `host_permissions` 由它派生，调用层无分支。
- **站点差异只在 `lib/adapters/sites.ts`**：解析逻辑通用，平台改版只改选择器，且解析失败有启发式回退。
- **网络请求只在 background**：content / popup 只收发消息，不直接调供应商 API。
- **UI 与逻辑解耦**：评论按钮通过 `window` 自定义事件通知面板，不依赖模块单例（打包拆 chunk 后仍成立）。
- **合规内建**：硬约束由程序追加；🤖 标识由 `finalizeDraft` 强制前置；没有发送相关代码。

## 扩展指南

**新增一个供应商**

1. 在 `lib/providers.ts` 的 `PRESET_PROVIDERS` 里加一条：`id`、`name`、`baseUrl`（含版本路径）、`models`、`defaultModel`、`keyUrl`、`hint`。
2. 不需要改任何调用逻辑；`host_permissions` 会自动包含它的域名。
3. `pnpm build` 重新构建。

**新增一个站点**

1. 在 `lib/adapters/sites.ts` 加一条配置：`hostPatterns`、`commentSelectors`、`textSelectors`、`authorSelectors`、`actionBarSelectors`、`replyBoxSelectors`、`replyOpenSelectors`、`threadItemSelectors`，以及可选的 `threadContextPattern`（只有命中该 URL 才带上下文）。
2. **同步修改 `entrypoints/content.ts` 的 `matches`**（两处必须一致，否则脚本不会注入到新站点）。
3. 在真实页面上用 DevTools 逐条验证选择器，再用 `pnpm dev` 实测按钮注入与填入。

**调整风格 / Prompt**

- 内置风格的名称与默认策略在 `lib/prompts/styles.ts`。
- 硬约束（禁脏话、歧视、100-200 字、只输出正文）在 `lib/prompts/index.ts` 的 `HARD_CONSTRAINTS`，不建议改。
- 只想微调措辞：用设置页的「Prompt 模板」（F7），支持 `{{author}}` `{{text}}` `{{styleName}}` `{{context}}` 四个变量。

**替换图标**

把 `public/icon/{16,32,48,96,128}.png` 换成自己的图（建议方形、深色背景上可辨识），`pnpm build` 后 `manifest.icons` 会自动指向它们，无需改配置。

## 质量与自查

- `pnpm test`：29 个用例，覆盖 Prompt 构建（🤖 标识、硬约束删不掉、上下文 / 情绪 / 自定义覆盖）、错误码翻译、情绪策略完整性、站点解析，以及 textarea 与 contenteditable 两种形态的「填入不发送」。
- `pnpm typecheck` + `pnpm build`：TypeScript 严格模式（含 `noUncheckedIndexedAccess`）与生产构建。
- 设置页「使用统计（仅本机）」：成功生成次数、成功率、平均耗时、复制率、填入次数，可一键重置——用来对照 PRD 指标（生成 ≤15 秒、编辑后复制率 ≥60%）。
- 未被单测覆盖的部分：Vue 组件渲染、真实网络请求、真实页面 DOM（需要装扩展手测）。

**已知行为边界**

- 讨论串上下文只在推文详情页 / 微博正文页生效，时间线首页不带（避免把无关推文当「此前的讨论」）。
- 流式超过 45 秒没有任何新片段，会被判定为卡住并提示重试。
- 换风格只在「已有草稿或报错」时才自动重生成，避免首次打开就白跑一次请求。

## 存储与隐私

| 数据 | 位置 |
| :--- | :--- |
| 当前激活配置（供应商 id + 模型） | `chrome.storage.sync` |
| 各供应商 API Key | `chrome.storage.local`（不参与云同步） |
| 自定义供应商、风格偏好、Prompt 模板、语气分析开关、隐私告知标记、使用统计 | `chrome.storage.local` |

- 源码零硬编码密钥；不采集浏览记录；不设中转服务器；使用统计不出本机。
- 评论文本只在生成时发送给你选定的供应商，插件不做额外留存。

## 权限说明

| 权限 | 用途 |
| :--- | :--- |
| `storage` | 保存配置、Key、Prompt 与统计 |
| `host_permissions`（5 家预设域名） | 调用预设供应商的 OpenAI 兼容接口 |
| `optional_host_permissions` | 仅在你保存 / 测试**自定义**供应商时，按需申请那一个域名 |
| content script（`x.com`、`weibo.com`） | 注入评论按钮与草稿面板 |

**上架审核要点**：定位写成「辩论辅助」；权限最小化（不申请 `<all_urls>`）；明确无自动发送；AI 生成内容固定带 🤖 标识；隐私政策说明「评论文本会发送至用户自选的 AI 供应商、插件本身不中转」。

## 排错

| 现象 | 可能原因 | 处理 |
| :--- | :--- | :--- |
| 评论旁没有「AI 回复」 | 站点选择器失效 / 页面没刷新 / 不在匹配站点 | 刷新页面；确认 URL；改 `lib/adapters/sites.ts` 后重新构建 |
| 点按钮面板不出现 | content script 未注入、或后台脚本报错 | 刷新页面；在 `chrome://extensions` 的扩展详情里查看 service worker 报错 |
| 面板空白 / 一直「正在写」 | 后台断开或流卡住 | 45 秒会自动提示；点「重试」，或换一家供应商 |
| 测试连接 401 / 404 / 429 | Key、路径、额度问题 | 见上文错误码对照表 |
| 「填入回复框」没反应 | 找不到编辑器（页面结构变了） | 会自动回退为复制；可手动粘贴；更新选择器 |
| 换风格没重新生成 | 还没生成过任何草稿 | 先点「生成草稿」 |
| 草稿被截断 | 模型 `max_tokens` 限制 | 点重新生成；或在设置里换能力更强的模型 |

## 已知限制

- **选择器需维护**：`x.com` / `weibo.com` 的 DOM 结构随时会变，改版后只需更新 `lib/adapters/sites.ts`。
- **仅支持两个站点**：其它平台需要新增适配配置（见扩展指南）。
- **填入依赖编辑器实现**：textarea 与 contenteditable 两条路径都做了，仍可能因平台改版失效，失败会回退为复制。
- **打包体积**：`background.js` 约 400 kB，主要来自 `openai` SDK；如需精简可改手写 fetch + SSE。
- **Firefox 未验证**：`pnpm build:firefox` 保留，但没有实测。
- **单测范围有限**：只覆盖纯函数与适配层，UI 与真实网络靠手测。

## 路线图

- 更多站点适配（知乎、B 站、Reddit 等）
- 用 fetch + SSE 替代 SDK，压缩 background 体积
- Firefox 验证与上架材料准备
- 配置导入 / 导出（换设备免重配）
- 草稿历史（跨评论保留最近几条）
